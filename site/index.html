AML evaluation harness

A Python and DuckDB pipeline over 179.7M synthetic transactions (IBM AMLworld) on a single Azure VM: 32 point-in-time SQL features, account-day alerts ranked within each day, and precision/recall at a daily review budget reported next to a random-ranker baseline and the attainable ceiling. Evaluation methodology on synthetic data, not a production detector.

Pipeline

  1. Ingest: CSV to Parquet with a positional schema and a txn_id checked to be 1..N.
  2. Labels: ring file parsed and LEFT JOINed back on a de-duplicated content key.
  3. Split: temporal cut, whole rings assigned by start date, test rings sharing an account with training dropped, four assertions.
  4. Features: 32 DuckDB window features over a two-sided event stream, every frame ending 1 MINUTE PRECEDING.
  5. Train: logistic regression, HistGradientBoosting, LightGBM; matrix streamed from DuckDB, ORDER BY txn_id.
  6. Evaluate: (account, day) grain, score = max, label = max, top-k per day at k = 10 to 1,000.

HI-Large on Azure: LightGBM, 3 seeds

HI-Medium: why the baseline matters

After the cut, the generator winds down: daily volume falls from 3,021,866 transactions to 7, so the last days are mostly positives and a random ranker already scores high on the pooled window. The 7 volume days are the fair comparison.
